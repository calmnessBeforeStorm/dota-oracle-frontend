# CLAUDE.md — dota-oracle-frontend

SPA системы прогнозирования исходов профессиональных матчей Dota 2.
Полная спецификация: [docs/spec.md](docs/spec.md) — ссылки «§8.1» ниже указывают на её разделы.
Бэкенд живёт в соседнем репозитории `dota-oracle-backend`.

## Стек

React 18 + TypeScript · Vite 6 · TanStack Query (данные) · TanStack Router (роутинг,
code-based дерево) · Tailwind CSS · Recharts · нативный WebSocket · Vitest + Testing Library.

## Текущее состояние

Фаза 6 по §11. F1–F6 работают на живых данных: лента live, карточка матча с составами,
драфтом и таймлайном, календарь и страница турнира, дашборд точности с калибровочной кривой.
Дев-сервер проксирует `/api` и `/ws` на `localhost:8100`.

## Инварианты — нарушать нельзя

1. **Ничья в Bo2 — отдельное состояние.** `winner_team_id: null` может означать и «ещё не
   решено», и «1–1». Различает их флаг `is_draw`; рендерить счёт только через
   `seriesStatus()` / `seriesScoreLabel()` из `lib/series.ts`, не собирать строку руками (§5.5).
2. **Задержка трансляции всегда видима.** Рядом с live-вероятностью обязателен
   `StreamDelayNotice`: наши числа опережают то, что видит зритель, и без предупреждения
   это читается как спойлер (§7.4).
3. **Атрибуция Liquipedia (CC-BY-SA) и дисклеймер Valve — на всех страницах**, где
   показываются их данные. `Attribution` смонтирована в `routes/root.tsx`; убирать нельзя (§13).
4. **Никаких формулировок про ставки.** Сервис аналитический; появление коэффициентов,
   «прогнозов на исход» в терминах беттинга или сравнения с букмекерами — вне скоупа (§13).
5. **Вероятности не выдумывать на клиенте.** `bo2NaiveOutcomes()` — плейсхолдер до v2, его
   вывод нельзя подписывать как результат модели: карты не независимы (§5.5).
6. **Метрики модели показывать по срезам минут.** Усреднённая цифра врёт: на 40-й минуте
   задача тривиальна (§7.2). Страница `accuracy` устроена именно так.
7. **Сторона события — не та сторона, которую событие называет.** Событие по строению
   называет сторону, которая его **потеряла**, а рошан и первая кровь — сторону, которая их
   сделала. Инверсия выглядит правдоподобно в обе стороны и красит все башни в неверный
   цвет, поэтому она живёт в одном месте — `beneficiaryIsRadiant()` в `lib/timeline.ts` —
   и покрыта тестом. Руками не повторять.
8. **Исход серии имеет три состояния, а не два.** Победитель известен, ничья 1–1, и
   **исход неизвестен** — последнее у подавляющего большинства серий, потому что
   `winner_team_id` проставляет `link-stages` только для лиг, сопоставленных с Liquipedia.
   Рисовать «идёт» для серии, сыгранной полгода назад, нельзя, и вывести исход из счёта
   тоже: без формата 1:0 — это и законченный Bo1, и брошенный Bo3.
9. **С WebSocket приходят не только прогнозы.** Сервер шлёт `{"type":"ping"}`, когда матч
   молчит, — так он замечает закрытую вкладку. Эти кадры отдавались в `onUpdate` как
   обычные точки, и карточка матча рисовала `NaN%` вместо главной цифры продукта через
   пять секунд после открытия. Фильтр в `api/ws.ts` проверяет **форму** кадра
   (`minute` и `p_radiant` — числа), а не отсутствие `type: 'ping'`: следующий служебный
   кадр не должен вернуть эту дыру.
10. **Порядок драфта известен не всегда.** У идущего матча табло отдаёт пики и баны
   по сторонам и не нумерует их сквозно — чередование теряется до разбора реплея.
   `DraftStrip` принимает `orderIsKnown` и меняет подпись; утверждать «слева направо —
   порядок драфта» там, где порядка нет, нельзя.
11. **Сетки турнира нет и не будет из этих данных.** У серии нет ни раунда, ни связи
   «победитель проходит дальше», а плей-офф в Dota почти всегда double elimination —
   восстановить верхнюю и нижнюю сетку по датам невозможно. Нужны шаблоны сеток
   Liquipedia; до тех пор F4 показывает список серий по стадиям.
12. **Дашборд точности не имеет права льстить.** Три правила, каждое ловит свой способ
   соврать: метрики без данных рисуются прочерком, а не нулём (нулевой log loss — это
   безупречная модель); версии моделей не смешиваются, и если у отдаваемой версии сверенных
   прогнозов ещё нет, страница так и говорит вместо того, чтобы показать калибровку прошлой;
   а честный знаменатель — матчи, а не прогнозы: четырнадцать матчей дают четыреста строк,
   и таблица из корзин по семьдесят читается как надёжный замер. Пороги и форматирование —
   в `lib/metrics.ts`, покрыты тестами.
13. **Холдаут и боевая выборка — разные измерения, и складывать их нельзя.** Холдаут —
   отложенный срез разобранных реплеев, много матчей, оценён один раз офлайн; боевая выборка —
   то, что реально видели посетители, из живого табло, и она по построению покрывает только
   матчи, шедшие в эфире **пока работала эта версия**. Пока на странице было только второе,
   «сверено 9 матчей» читалось как «модель не проверяли», хотя её оценили на 1293. Обе цифры
   стоят рядом в `TrainingStatus`, и показывать вместо одной другую — та самая лесть, против
   которой написан инвариант 12.
14. **Типы API — зеркало бэкенда.** При изменении схем править `src/api/types.ts` в том же PR;
   источник истины — `localhost:8100/openapi.json`.

## Команды

```bash
npm install
npm run dev          # localhost:5273, /api и /ws проксируются на localhost:8100
npm test             # vitest
npm run lint         # eslint
npm run typecheck    # tsc --noEmit
npm run build        # tsc -b && vite build
```

Для полноценной работы нужен бэкенд, и он запускается **не** в докере: в
`dota-oracle-backend` поднимаются хранилища (`docker compose up -d`), а API стартует руками
из venv на Python 3.12 (`.venv/Scripts/python.exe -m uvicorn app.main:app --reload --port 8100`).
Подробности — в `../dota-oracle-backend/CLAUDE.md`.

## Правила ведения репозитория

Общие правила пары репозиториев — в `../CLAUDE.md`, коротко:

- Дефолтная ветка — **`development`** (тестовый сервер). Вся работа ветвится от неё.
- Каждая фича — отдельная ветка от `development`: `feature/<кратко>`, `fix/<кратко>`.
  Прямых коммитов в `development` нет, только мердж.
- **В `main` категорически нельзя коммитить и пушить.** Единственный путь кода в прод —
  мердж `development` → `main`, и он делается **только по явному разрешению владельца
  проекта на этот конкретный мердж**. Разрешение не переносится на следующие разы.
  По своей инициативе в `main` не ходить и не предлагать этого.
- Коммиты подписываются почтой **`ersaim.adilet@yandex.kz`** (локальный `user.email` уже
  прописан в репозитории, не перезаписывать глобальным).
- **Сообщения коммитов — на английском**, в императиве: `add series score component`, а не
  `added changes`. Трейлеры об авторстве ИИ не добавляются.
- Перед пушем прогнать то же, что гоняет CI:
  `npm run lint && npm run typecheck && npm test && npm run build`.
